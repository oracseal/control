# Control 0.5.0

개발·분석 작업에서 **문제 이해 → 전체 설계·계획 → 구현·검증 → 방향 조정 → 본인 설명**을 연결하는 일반용 Skill이다. 사용자는 목적과 중요한 판단을 결정하고, Codex는 합의한 범위에서 작업하며 선택과 결과의 근거를 보여 준다.

## 시작

저장소 이름은 `control`이다. Clone/다운로드한 뒤 [start.md](start.md)의 실제 경로를 읽으라고 요청한다. 작업 폴더(TASK)와 스킬 폴더(KIT)를 구분하고, 스킬 파일을 결과물에 포함할지는 프로젝트의 패키징 기준을 따른다. 자동 Skill 검색 경로에 설치하지 않았어도 파일을 직접 읽혀 적용할 수 있다. 설치된 스킬의 호출명은 `$control`이다.

첫 응답은 문제·목표·제약, 전체 구조와 대안, 완료까지의 작업 계획, 검증·담당자 질문, 추천하는 첫 작업 범위를 제안한다. 사용자가 범위를 정하면 그 안에서 구현·검증한다. 이후 매 대화에서 새 정보와 현재 계획을 대조해 유지 또는 수정 이유와 다음 행동을 알린다. 이미 승인한 작업을 재개할 때 같은 승인을 반복해서 요구하지 않는다.

담당자와의 첫 대화는 **"어떤 정보를 답해 주실 수 있나요?"**로 시작한다. 작은 확인 질문을 허용하고, Codex는 실제 답을 받을 때마다 새로 알게 된 점과 남은 궁금증을 정리해 후속 질문을 제안한다. 사례·판단 과정·예외로 대화를 발전시키며, 이미 답한 질문을 반복하거나 해결책·설계를 통째로 요구하지 않는다.

핵심 파일:

- [start.md](start.md): 첫 분석과 전체 계획, 범위 결정.
- [SKILL.md](skills/control/SKILL.md): 작업 권한, 구현·검증·계획 갱신, 상황별 참조.
- [structure.md](skills/control/references/structure.md): 작업에 맞는 구조·대안·작업 분해.
- [stakeholder.md](skills/control/references/stakeholder.md): 답변 범위 확인, 작은 질문과 후속 탐색, 중복 방지, 답변 반영·대화 종합.
- [evidence.md](skills/control/references/evidence.md): 예상·실제 비교와 근거 관리.
- [ai-decisions.md](skills/control/references/ai-decisions.md): AI 선택의 근거·대안·위험과 사용자 이해.
- [git-checkpoints.md](skills/control/references/git-checkpoints.md): 검증·사람 확인 후 정확한 파일 목록으로 로컬 커밋.

## 작업에 남길 증거

| 역량 | 실제 행동과 결과 |
|---|---|
| 문제·목표 구체화 | 사용자와 업무 문제, 필수 요구·성공 기준, 사실/가정/미확인, 유지할 제약을 구분한다. |
| 전체 설계·작업 분해 | 데이터 흐름과 책임을 설계하고, 선행 조건·허용 파일·검사·사람 확인이 있는 중간 점검 단위로 나눈다. |
| 의도 갱신·맥락 유지 | 매 대화에서 계획을 대조한다. 새 답과 검증 결과가 판단을 바꾸면 현재 범위·계획·설계·검사·문서를 함께 갱신한다. |
| 요구 충족·기능 정확성 | 요구→구현→입력/예상→실제 결과를 연결한다. 실패 시 원인 근거·수정 범위·유지 조건부터 설명하고 재검증한다. |
| 유지보수성·결과물 완성도 | 실제 스키마·책임·교체 파일/설정·설계 근거를 README 또는 허용된 설계 문서에 남기고 코드·검사와 대조한다. |
| 동작·구조·위험 이해 | 핵심 입력의 처리 경로, 실패/경계 사례, 규칙이 바뀔 때 수정할 위치를 설명하고 사용자의 실제 설명을 확인한다. |
| AI 의사결정 이해 | AI가 고른 방법의 근거·버린 대안·성립 조건·비용·재검토 조건을 설명한다. 구현 완료와 이해 확인을 별도로 기록한다. |
| 탐색·정보 종합 | 작은 질문을 실제 답에서 발전시키고 여러 대화의 범위·사용 흐름·피드백 형식·제외 사항·제약을 현재 MVP 요약으로 통합한다. 필요하면 담당자에게 되돌려 보낼 확인 문구를 제안한다. |

작업 기록은 기존 작업 형식을 우선한다. 별도 형식이 없으면 [DECISIONS.md·NOTES.md의 최소 기록](skills/control/references/work-record.md)을 사용한다. 문서·테스트·커밋의 개수가 품질을 대신하지 않는다. 새 기술·모델·의존성은 해결할 문제와 구현·운영·검증·설명 비용을 비교해 선택한다.

**원격 저장소에 연결되지 않아도 로컬 커밋은 가능하다.** 기존 로컬 저장소를 사용하고, 로컬 저장소도 없으면 작업 폴더의 초기화·기준점 커밋부터 제안한다. GitHub 로그인이나 remote 설정을 요구하지 않는다. 작업 단위별 검증·사람 확인·승인 후 정확한 파일만 커밋하고 실제 SHA를 확인한다.

## 적용 원칙

현재 사용자의 요청·수정 사항과 프로젝트 지침을 기준으로 적용한다. 특정 조직·플랫폼의 도구나 시간 제한을 전제하지 않는다. 기존 작업을 보존하고, 외부 전송·원격 Push·배포 등은 사용자가 승인한 범위와 환경의 권한을 따른다. 로컬 커밋 승인을 외부 작업의 승인으로 확대하지 않는다.
